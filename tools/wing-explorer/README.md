# wing-explorer

A window onto a grandMA3 command wing: the desk drawn, what is pressed and moved shown
live, LEDs and faders drivable, and a few demo programs. The protocol is
`crates/pult-wing`; the USB handle and the page are here — the split
`pult-mvr-xchange` and `infra/interop/xchange` already have.

```
cargo run -p wing-explorer          # then http://localhost:7800
cargo run -p wing-explorer -- --no-device   # draw the panel with no wing attached
```

Two things it needs from a local grandMA3 install, **neither of which it ships**:

* `hardware_configurations.xml`, which names every index. It is read where it lies, at
  startup, by `pult_wing::WingMap::from_xml` — there is no conversion step and nothing
  derived from MA's table is left on disk. `--map` points at another copy, `--module`
  at another wing;
* `command_wing_app.bin`, which the wing asks for at every single connect, because what
  lives in its flash is only a bootloader. It is found automatically in the newest
  grandMA3 under `~/MALightingTechnology`; `--image` overrides.

**grandMA3 must not be running.** One process can own the interface, and it will be
whichever got there first.

## What is drawn is authored

MA's table says what every index *is* and nothing about where it sits — there are no
coordinates anywhere in its resources. So `ui/layout.json` is ours, generated by
`ui/make-layout.py`, and it is a schematic of the desk rather than a photograph of one.
It holds geometry and indices only; the names come from the control map at runtime, so
nothing of MA's is checked in. Correct it against the real panel:

```
python3 ui/make-layout.py > ui/layout.json
```

The executor strip draws a fader, the hardkey that is its touch contact and the `EXEC`
button of the same executor in one column, because that pairing is the thing the
capture proved — two independent decodings landing on executor 202 is what made the
index rules believable.

## The demo programs

`off`, `rest` (everything dim, the way grandMA3 leaves it), `chase` (one lit channel
walking the frame, which is how you check the LED table's offsets against the panel by
eye), `breathe`, `rainbow` (every RGB LED through the hues) and `named` — which lights
only the keys MA's table gives a name to, and is therefore a picture of the control map
itself. Touching any control by hand stops the demo painting over it.

## If it will not come up

The wing resets whenever the host stops talking, so a bad run leaves nothing behind —
see *The one way to brick it* in `docs/WING-PROTOCOL.md`. Stop everything, wait a few
seconds and start again; the bootloader will be back and announcing.
